# GIF 与视频理解增强

让 AstrBot 真正理解 GIF 动图和短视频，而不只看见某一瞬间。支持提取视频声音，交给具备音频模态的主模型。

**发送媒体，照常提问即可，无需额外识别命令。**

[快速开始](#快速开始) · [功能说明](#功能说明) · [配置说明](#配置说明) · [缓存管理](#缓存管理) · [常见问题](#常见问题)

## 快速开始

1. 在 AstrBot 中安装 **GIF 与视频理解增强**（`astrbot_plugin_read_gif`）。
2. 使用 AstrBot **内置 Agent**（`agent_runner_type = local`），选择支持看图的主模型；主模型不能看图时，也可以配置 AstrBot 的图片转述模型。
3. 如果需要处理视频，请在 **AstrBot 实际运行的环境**中准备好 `ffmpeg` 和 `ffprobe`，确保它们可通过 `PATH` 找到。只使用 GIF 不需要这两个工具。
4. 发送 GIF 或视频，按平时的方式触发机器人，例如：
   - “这个动图里的角色做了什么？”
   - “请概括这段视频。”
   - “结合画面和声音，解释发生了什么。”

也可以引用包含 GIF 或视频的消息提问，前提是聊天平台能够提供被引用的媒体文件。

**也支持以普通文件附件发送或引用的媒体**，例如 QQ 群文件；不限于 QQ，平台只需向 AstrBot 提供可读取的文件组件及文件名。动图文件支持 GIF、动态 WebP、APNG（含 `.png` 后缀），共用 GIF 宫格及提示词设置；视频文件沿用现有视频设置。原附件保留，只追加识别所需的画面和可选音轨。

> 使用 Docker 时，FFmpeg 和 ffprobe 必须在容器内可用，只装在宿主机上不够。插件不会自行下载这两个程序。更改 `PATH` 后，需要重启 AstrBot 进程。

## 功能说明

### 看连续画面

插件均匀选取若干帧，按**从左到右、从上到下**的顺序拼成一张图，供模型比较前后的变化。

- **GIF**：按帧序号均匀选帧，保持画面比例拼接，不添加文字。
- **视频**：按时间均匀采样，保持画面比例紧密拼接，不为凑正方形额外填黑边，也不裁切画面。相邻列之间留有 3 像素黑色间隔，便于分辨每帧边界；不添加外围边框。原视频自带的黑边仍会保留。
- **视频标记**：顶部显示视频编号和总时长，每帧上方显示采样时间。文字有独立区域，不遮挡画面。
- **多段视频**：通过编号对应画面、时间说明和音轨。

宫格图进入原来的聊天请求，不会额外发起一次独立的“视频分析对话”。如果启用了图片转述，由转述模型先看图，再把文字描述交给主模型。

**采样不等于看过每一帧。** 快速闪过的内容、细小字幕和复杂动作可能遗漏。格子越多，覆盖的时刻越多，但同样大小的图片中，每格也会更小。

### 结合视频声音

“理解视频中的音频”默认开启：

- 有声音时提取音轨，通过 AstrBot 的音频输入接口交给主模型。
- 没有音轨或整段完全静音时，不发送音频。
- 关闭开关、音轨处理失败，或当前主模型不具备可用的音频输入能力时，只提供画面。

这不是语音转文字功能，不会另调语音识别服务。**主模型及其实际接口都需要支持音频输入**，并正确配置音频模态。插件不会根据模型名称猜测能力；未配置模态的兼容模式可能允许尝试，但不保证服务端接受音频。Anthropic 适配器不提交本插件的音频附件。

图片转述模型只看图，不接收视频音轨。声音仅交给主模型；音频已提交也不代表模型一定理解正确。若服务端拒绝音频，请检查模型配置或关闭此开关。

> 图片和音频都可能增加模型用量。进入同一次聊天请求，不代表没有额外费用。

### 保留原视频

插件追加宫格和可选音轨，不替换原视频附件。框架仍可提供原附件信息，并按原有方式处理它。

插件不会为了分析再复制一整份视频：已有可读取的本地文件时直接使用；只有远程来源时，由框架获取文件。下载后的原视频仍由框架或平台适配器管理，插件缓存清理不会删除它。

## 配置说明

在 AstrBot WebUI 的插件配置页调整。通常保持自动宫格即可。

| 配置项 | 默认值 | 如何选择 |
|---|---|---|
| 宫格预设 | `auto` | GIF 与视频共用。可选自动、4、9、16、25、36 格，对应 2×2 至 6×6 |
| GIF 自动宫格阈值 | 1 / 10 / 20 / 30 秒 | 分别达到这些时长时，切换至 9 / 16 / 25 / 36 格 |
| 视频自动宫格阈值 | 5 / 15 / 30 / 45 秒 | 与 GIF 独立，分别切换至 9 / 16 / 25 / 36 格 |
| 宫格图长边限制 | 1800 像素 | GIF 与视频共用；视频的编号、时间戳也计入尺寸。更大通常更清晰，但可能增加用量 |
| 视频时长上限 | 90 秒 | 支持小数；留空不限。超限跳过整段视频的增强处理，不截取前半段 |
| 理解视频中的音频 | 开启 | 不需要声音或接口不支持音频时关闭 |
| GIF 动图提示词 | 内置文本 | 提醒模型把采样画面当作动画理解；留空关闭 |
| 视频理解提示词 | 内置文本 | 提醒模型按时间顺序理解视频；留空不影响编号、时长、采样时间等事实说明 |
| 自动清理缓存间隔 | 60 分钟 | 后续请求触发到期检查，不是后台定时任务；设为 0 关闭 |
| 缓存文件最大保留时长 | 24 小时 | 自动清理时删除过期缓存 |

### 自动档怎样选择？

| 格数 | GIF 时长 | 视频时长 |
|---|---|---|
| 4 | 小于 1 秒 | 小于 5 秒 |
| 9 | 1 秒至不足 10 秒 | 5 秒至不足 15 秒 |
| 16 | 10 秒至不足 20 秒 | 15 秒至不足 30 秒 |
| 25 | 20 秒至不足 30 秒 | 30 秒至不足 45 秒 |
| 36 | 30 秒及以上 | 45 秒及以上，且不超过视频时长上限 |

- 固定档不使用时长阈值。
- 每组四个阈值必须为有限正数，且严格递增；无效时该组使用默认值。
- 实际帧数不足时，自动档会减少格数。视频固定档也会减少格数，不重复填帧；GIF 固定档用最后一帧补足。
- 视频时长上限填写 0、负数、非有限数或无效文字时，按 90 秒处理。该限制不限制 GIF。
- 视频长边设置会限制在 128～4096 像素范围内；框架和模型仍可能进一步缩图。

**建议先用默认配置观察结果。** 想多看几个时刻，可以增加格数；想看清字幕或小物体，可以减少格数或适当提高输出尺寸。去掉额外黑边让拼图更紧凑，但不会恢复源文件本来就没有的细节。

配置页中已有的设置会保留，表中的默认值不会覆盖已保存的数值。自定义自动阈值时，请确认四个值依次增大。

## 缓存管理

插件保存宫格 PNG、可选 WAV 音轨和小型索引，不保存单独的散帧图片。相同媒体和处理参数可以复用缓存。

### 查看宫格

```text
/gifcache          列出最近 20 张缓存宫格图
/gifcache 3        发送列表中的第 3 张图
/gifcache abc      按文件名中的片段查找并发送
```

该命令同时支持 GIF 和视频宫格，不发送音轨或索引。

### 清理缓存

```text
/gifclean
```

清理插件生成的缓存，不删除原视频。正在生成或当前请求仍在使用的视频缓存会暂时跳过，可在请求结束后再次清理。

## 常见问题

**为什么没有处理视频？**

先确认 FFmpeg、ffprobe 在 AstrBot 环境中可用，再检查视频是否超过时长限制、是否损坏，以及平台是否提供了可读取的 `Video` 视频组件或带有支持后缀的 `File` 文件组件。只有引用文字摘要、网页链接或播放列表时，不会自动寻找原视频。

**视频处理失败会打断聊天吗？**

插件会保留原视频组件，尽量让框架继续处理，不因单个视频失败而中断 GIF 或其它媒体处理。文件获取失败时，会向模型提供经过链接脱敏的错误原因；缺少工具、超限或解码失败等情况记录在日志中，不追加宫格。

**哪些视频可以尝试？**

支持尝试 MP4、MOV、MKV、WebM、AVI 等常见容器，能否读取还取决于实际编码和 FFmpeg 构建。单个源文件上限为 512 MiB；视频处理有 120 秒超时，音轨输出上限为 32 MiB。留空时长上限不会取消这些保护，也不会取消分辨率和格式检查。

**普通文件附件支持哪些格式？**

- 动图：GIF、动态 WebP、APNG（`.apng` 或 `.png`）。APNG 的独立默认封面不计入动画采样。
- 视频：MP4、M4V、MOV、MKV、WebM、AVI、FLV、MPG/MPEG、TS/MTS/M2TS、3GP/3G2、WMV/ASF、OGV、RM/RMVB。实际能否解码仍取决于内容及 FFmpeg。
- 先按文件名后缀筛选，再检查实际内容；大写后缀也支持。静态图片保持原样，文档和压缩包不因本插件而下载检查。无文件名时尝试已提供的路径或链接后缀，不猜测无后缀文件。
- 动图附件上限为 64 MiB、2000 帧、单帧 16777216 像素，所有帧像素总量不超过 2 亿；视频沿用原有限制。
- 本插件等待框架取文件最多 60 秒。大小限制在取得本地文件后检查，**不是下载流量上限**；原附件及其下载文件不由插件缓存清理删除。
- 获取或处理失败会向本轮模型提供“可告知用户，也可继续处理”的错误说明，不追加识别画面。原附件仍交给框架处理，框架自身的下载或文件工具错误不由插件接管。

**为什么模型仍然看不清，或漏掉一段动作？**

宫格只是均匀采样，不会自动挑选重要情节。输出尺寸、格数、原始清晰度，以及框架和模型的图片处理都会影响结果；长视频尤其容易漏掉短暂细节。

**引用消息或第三方 Agent 能用吗？**

引用消息需要平台适配器提供原媒体，只有文字摘要无法还原内容。本插件针对 AstrBot 内置 Agent 工作，第三方 Agent 不保证生效。框架升级后，建议检查直接发送、引用消息及图片转述是否正常。

## 文件结构

```text
插件目录
├─ main.py                  消息处理、模型接入与缓存命令
├─ gif_processor.py         GIF 选帧与拼图
├─ video_processor.py       视频采样、拼图与音轨处理
├─ media_config.py          时长与自动阈值校验
├─ _conf_schema.json        配置页面定义
├─ requirements.txt         Python 依赖
└─ metadata.yaml            插件信息

AstrBot 数据目录
├─ config/astrbot_plugin_read_gif_config.json
└─ plugin_data/astrbot_plugin_read_gif/
   ├─ gif_grid_*.png         GIF 宫格
   ├─ video_grid_*.png       视频宫格
   ├─ video_grid_*.json      采样时间等索引
   ├─ video_audio_*.wav      音轨
   └─ video_audio_*.silent   完全静音的检测记录
```
