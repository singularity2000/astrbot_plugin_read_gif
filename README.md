# GIF 与视频理解增强

将 GIF 动图与视频抽帧拼成宫格图，帮助模型理解连续画面；支持通过 AstrBot 的音频输入接口，让主模型结合视频声音回答。

插件标识：`astrbot_plugin_read_gif`

> **保留原视频，按需追加理解材料。** 成功时增加宫格与可选音轨；失败时只记日志，交还 AstrBot 原生流程。

## 它是怎样工作的？

模型收到一张静态图片，可以描述这一刻的画面；但要理解一个动作或一段视频，还需要知道画面如何随时间变化。本插件不让模型直接读取完整视频，而是在 AstrBot 准备调用模型时，将媒体转换成适合图片输入的形式：

```text
GIF 动图 → 均匀选帧 → 拼成宫格图 → 模型看图理解

视频文件
├─ 保留原附件 → 框架提供文件名、绝对路径和引用标记
├─ 按时间采样 → 标注编号与时间 → 宫格图
└─ 开启音频理解且非静音 → 提取音轨 → 支持音频输入的主模型直接听
```

例如，一段视频被拆成 9 个采样画面，模型就可以比较动作前后、场景变化，而不只描述其中一帧。**这些画面只是采样，不等于看过视频的每一帧**：快速闪过的内容、细小字幕、复杂动作仍可能遗漏。

**宫格是补充，不是原视频的替代品。** 原视频组件仍由 AstrBot 处理，模型继续收到原生的视频附件名称、绝对路径；引用视频时保留引用附件标记。路径指向 AstrBot 所在环境的文件：Windows 使用 Windows 路径，Linux 使用 Linux 路径，Docker 使用容器内路径。它不是公开下载链接，也不保证另一个工具所在的沙箱能访问。

插件不单独启动一次“视频分析对话”。宫格图进入原来的聊天请求；支持直接音频输入时，声音也进入同一次请求。如果你的主模型不能看图，但已配置 AstrBot 图片转述模型，宫格图仍可先转述为文字，再交给主模型。

## 安装与使用

1. 在 AstrBot WebUI 中安装本插件。
2. **使用视频功能前，确认 AstrBot 的运行环境能找到 `ffmpeg` 和 `ffprobe`。** 仅使用 GIF 不需要这两个工具。插件不会自行下载或安装可执行文件。
3. 主模型应支持图片输入，或已配置可用的图片转述模型。若需要听视频声音，主模型及实际调用接口还应支持音频输入，并正确设置模型的音频模态。
4. 在聊天中发送视频或 GIF，并按平时的方式触发机器人，例如：“请描述这个动作”“这段视频里发生了什么”。也可以引用包含媒体的消息提问。

无需另输视频识别命令。插件只在触发模型请求时工作，不会自动处理群内收到的每个视频。

### 运行环境说明

- **GIF 依赖 Pillow**，由 `requirements.txt` 声明；AstrBot 环境通常已有。
- **视频依赖 FFmpeg 与 ffprobe**，需要支持对应视频的解码器。它们通过系统 `PATH` 查找；只在宿主机安装、不在 Docker 容器中安装，对容器内的 AstrBot 无效。更改 `PATH` 后应重启 AstrBot 进程。
- 常见 MP4、MOV、MKV、WebM、AVI 等容器可尝试处理，是否成功还取决于实际编码和 FFmpeg 构建。不会仅凭文件后缀判断内容；不支持把播放列表或网页链接当作视频文件解码。
- 缺少工具、文件损坏、超限或无法解码时，插件不为该视频追加宫格、提示或错误说明，只记录诊断日志，并保留原组件交回 AstrBot。框架仍可按自身逻辑处理附件；GIF 和其它消息不受这项失败影响。
- 适用于 **AstrBot 内置 Agent（`agent_runner_type = local`）**。第三方 Agent Runner 不经过相同的准备钩子，不保证本插件的 GIF/视频替换生效。
- 平台必须提供可读取的媒体文件或下载地址。引用消息还需要适配器提供原消息的媒体组件；仅有“视频”文字摘要不能还原原文件。

## 配置说明

在 AstrBot WebUI 的插件配置页调整。已有 GIF 配置、英文插件标识和数据目录保持不变。

| 配置项 | 默认值 | 作用 |
|---|---|---|
| 宫格预设 | `auto` | GIF 与视频共用，可选自动、4、9、16、25 格 |
| GIF 自动宫格阈值 | 1 / 10 / 20 秒 | 三个数字输入，控制自动档何时切换至 9、16、25 格 |
| 视频自动宫格阈值 | 5 / 15 / 30 秒 | 三个数字输入，与 GIF 阈值独立 |
| 宫格图长边限制 | 1600 像素 | 共用的输出大小设置；越大通常越清晰，但可能增加模型用量 |
| GIF 动图提示词 | 内置文本 | 引导看图的模型将 GIF 宫格理解为动画；原有默认文本不变 |
| 视频理解提示词 | 见下文 | 引导看图的模型按视频理解；可自定义或清空 |
| 视频时长上限 | `60` | 秒数，支持小数；留空不限时长 |
| 理解视频中的音频 | 开启 | 对非静音音轨尝试使用框架的主模型音频输入，不额外调用转写服务 |
| 自动清理缓存间隔 | 60 分钟 | 达到间隔后，在后续模型请求准备时检查缓存；0 关闭自动清理 |
| 缓存文件最大保留时长 | 24 小时 | 自动清理过期缓存；视频缓存按最近使用时间续期 |
| 在 Info 日志中显示 Debug 信息 | 关闭 | 提高本插件诊断日志的可见性，便于排查 |

### 自动宫格规则

默认规则如下。**达到切换点就升档**，例如恰好 5 秒的视频使用 9 格。

| 宫格数 | GIF 默认时长范围 | 视频默认时长范围 |
|---|---|---|
| 4 | 小于 1 秒 | 小于 5 秒 |
| 9 | 1 秒至小于 10 秒 | 5 秒至小于 15 秒 |
| 16 | 10 秒至小于 20 秒 | 15 秒至小于 30 秒 |
| 25 | 20 秒及以上 | 30 秒及以上 |

两组切换点均支持小数，要求大于零、有限且严格递增。无效时，仅对应媒体类型的整组阈值回退默认值，并在日志中提醒；不会自动排序或改写用户填写的内容。固定 4/9/16/25 档不使用这些切换点。

GIF 保留原来的按帧序号均匀选帧方式；自动档在帧数不足时降为不超过帧数的完全平方数。GIF 固定档仍保留原来的不足帧补齐行为。

视频按播放时间采样，每格标注实际时间，整张图标注视频编号。视频帧不足时减格，不重复画面凑数；旋转信息和画面比例交给解码与缩放流程处理，空余位置留黑边，不拉伸画面。

> 更多格子不一定更清晰：同样的总分辨率下，每格会更小。以约 1600 像素的 25 格为例，每格长边约 310 像素；不适合保证小字识别。约一分钟的视频取 25 帧，也可能漏掉采样间隙中的短暂动作。

### 视频时长上限

这个设置使用文本输入框，以区分“留空”和“输入 0”。

- `60`：最多处理 60 秒，恰好 60 秒允许。
- `30.5`：最多处理 30.5 秒。
- 留空或只输入空格：不限制视频时长。
- `0`、负数、非数字、`NaN`、无穷大：按默认 60 秒处理。
- 升级时缺少这个配置项：使用默认 60 秒，不当作留空。

**超限只跳过本插件的视频增强，不截取前半段，也不禁止框架继续处理原附件。** 无法确定时长时同样透明回退。该限制只适用于视频，不影响 GIF。

留空不是取消全部保护：视频仍有 512 MiB 原文件大小上限、约 1660 万源画面像素上限，以及每个文件 120 秒的处理预算；文件获取另有 60 秒等待上限。大小检查发生在获得本地文件后，不能保证平台或框架不会先下载大文件。视频输出长边限制在 128～4096 像素之间；GIF 保持原有尺寸处理行为。

### 视频理解提示词

默认值：

> 消息可能包含宫格图。每组同编号宫格图中的画面来自同一段视频，按从左到右、从上到下的时间顺序排列。若附有同编号音频，请综合画面、对白及环境声音回答。请把这些画面作为视频的采样内容来理解。除非用户询问分析方式或需要说明局限，否则不主动提及“宫格”、“拼接”等技术细节。

GIF 与视频提示词分别配置。主模型直接看图时，注入主模型的系统提示；走图片转述时，将提示提供给真正看图的转述模型，而不是要求只收到文字的主模型“看图”。

清空提示词只关闭自定义引导，**不会移除视频编号、时长、采样时间和音频状态等事实说明**。同一消息包含多个视频时，用相同编号对应画面和音轨。

## 视频声音如何处理？

「理解视频中的音频」默认开启。插件不额外选择语音识别模型，也不调用语音转文字服务。

| 视频情况 | 实际行为 |
|---|---|
| 没有音轨 | 仅发送宫格图，说明原视频没有音轨 |
| 有音轨，但所有声道在分析范围内完全静音 | 不发送音频，说明音轨完全静音 |
| 有非静音音轨，且主模型及框架支持音频输入 | 将宫格和声音交给同一次主模型请求 |
| 开关关闭 | 不提取或检查声音；只看画面，不把它说成“无音轨” |
| 音轨处理失败、过大，或本轮不支持音频输入 | 保留画面理解，说明本次没有提供声音 |

完全静音检查会覆盖整段分析范围的全部声道，不只检查开头，也不把低于某个音量阈值的声音直接算作静音。时间基准以视频画面起点为准，音轨有起始偏移时会相应裁齐或补静音，使声音时间与采样时间可对应。

为兼容框架的音频输入，音轨导出为 **24 kHz、双声道、16-bit WAV**，并设 32 MiB 上限。这里可能重采样或转换声音格式，但**不会转码或另存完整视频**。极轻声音可能受到输出精度影响，多声道也会转换为双声道。

使用 Gemini 等音频输入模型时，要同时确认：

1. 当前模型支持的是**音频输入**，不只是语音输出。
2. AstrBot 中对应模型的音频模态配置正确。
3. 实际调用的服务或中转接口接受音频输入。

QQ 语音能得到回答不一定代表主模型直接听过：也可能是框架先执行了语音转文字。视频音轨在本插件中直接加入模型请求，不经过那条 QQ 语音转写流程。

插件会跳过明确未配置音频输入的模型，以及本地框架中只将音频替换为文字占位符的 Anthropic 适配器。对于框架沿用的空模态列表，会按“未配置、允许尝试”处理。模型切换、自动回退及第三方服务的真实支持情况仍由框架与服务端决定；**无法保证所有标注支持音频的接口都能调用成功**。服务端拒绝音频时，应检查配置或关闭此开关；插件不会另发一次付费识别请求来兜底。

> 音频与图片进入同一次请求，不等于没有额外费用。模型用量仍可能增加；关闭开关可只分析画面。若模型没有收到音轨，就不应推断对白、音乐或环境声音。

## 文件与缓存：会不会占两份视频空间？

**不会为了分析再保存一份完整视频。**

- 平台已经提供本地视频时，直接读取现有文件，优先使用可用的本地路径。
- 只有远程地址时，调用框架获取文件，将有效的本地绝对路径回填到原视频组件。即使后续抽帧失败，框架也可复用已取得的文件，避免本轮重复下载。若文件获取本身失败，则保留原来源，供框架重试或回退。
- 视频帧通过内存管道传递，不生成一堆散帧图片。
- 插件只保留宫格 PNG、可选 WAV 音轨和小型缓存索引；生成中可能短暂出现原子写入用的临时文件。
- 视频缓存包含内容哈希、宫格档位、输出尺寸和渲染版本，相同内容与参数复用结果。声音缓存独立复用，不因宫格档位变化重复保存。
- 插件缓存清理只处理自身产物，不删除原视频，也不把源视频加入“本轮结束即删除”的临时文件列表。原视频的保留与清理由 AstrBot、平台适配器及其原有策略决定。

**节省重复存储不等于零磁盘占用**：首次下载的原视频、宫格图和可选音轨仍需要空间。跨消息的原文件下载与保存策略还受平台适配器控制，插件不能保证整个 AstrBot 永远只有一份原视频。

## 缓存命令

保留原有命令名，GIF 和视频宫格均可查看。

### `/gifcache`

```text
/gifcache           列出最近 20 张缓存宫格图
/gifcache 3         发送列表中的第 3 张图
/gifcache abc       按文件名前缀或片段查找并发送
```

只列出 PNG 图，不发送 WAV 音轨或缓存索引。

### `/gifclean`

清理插件目录中的缓存，包括宫格、音轨和索引。正在生成或当前请求仍在使用的视频缓存会暂时跳过，避免清理与发送竞争；可以在请求结束后再清理。

自动清理只删除过期文件；手动清理不考虑文件年龄。自动清理是后续请求触发的检查，不是后台定时任务。

> **隐私提醒：缓存可能包含聊天画面和声音。** 这些命令沿用现有的全局缓存行为；需要限制访问时，请在 AstrBot 中配置命令权限，不要把它当作按会话隔离的相册。

## 兼容性与边界

- 普通 PNG、JPEG 等图片不经过 GIF/视频转换；GIF 根据文件头识别，不依赖后缀。
- 本插件识别消息中的 `Video` 组件，不默认把所有普通文件附件或网页链接当成视频。具体平台能否提供组件和引用内容，取决于适配器。
- 宫格有助于理解画面变化，但不能保证动作、字幕或对白识别准确。视频越长，固定格数能覆盖的细节越少。
- 宫格会继续经过 AstrBot 自身的图片处理和模型图片策略；实际发送清晰度还受框架与服务端限制。
- 图片转述模式下，模型能看到哪些直接图与引用图仍受框架转述机制影响。转述模型没有收到视频音频时，不应声称听过声音；音轨只交给主模型。
- 需要框架提供视频组件、请求准备钩子及图片输入支持。旧版请求结构若没有音频接口，则只提供画面增强；不能据此保证所有历史版本、平台和服务商均兼容。
- GIF 预处理保护和图片转述提示涉及框架内部流程，升级框架后建议验证直接发送、引用及混合媒体消息；不能保证与所有第三方插件的组合均兼容。
